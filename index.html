MIDAP A Full-Stack Open NPU Platform for Embedded AI Exploration

MIDAP (Memory In the Datapath Architecture Processor) is an open-source NPU (neural processing unit) platform built around a high-performance, adder-tree based CNN accelerator.

Architecture

MIDAP is engineered to maximize throughput-per-watt by minimizing DRAM access overhead.

Integrated SRAM

SRAM sits inside the datapath itself, so compute reads operands at on-chip latency instead of waiting on a shared bus or DRAM.

Multi-bank FMEM

A multi-bank feature-map memory (FMEM) keeps one layer's output on chip to be reused as the next layer's input — no DRAM round-trip between layers.

Fused Architecture

Convolution, activation, and reduction run back-to-back in one unified pipeline, so intermediate results never leave the datapath.

Why MIDAP

Two advantages define MIDAP: end-to-end execution and diverse model support — both on a single accelerator.

1

End-to-end execution

The entire network, on one accelerator

16+ operators execute on MIDAP with no CPU/GPU offloading, keeping MAC utilization high and DRAM access low.

  • Convolution
  • GEMM / GEMV / FC
  • Activation · GELU LUT
  • Dilated Convolution
  • Depthwise Convolution
  • Element-wise Add / Mult
  • Transposed Convolution
  • Pooling (max · avg)
  • Global Pooling
  • Nearest-Neighbor Upsampling
  • Bilinear Upsampling
  • Implicit Transpose
  • …and more

Coverage comes from the native datapath, CIM and reduction-module datapath extensions, tensor virtualization, and compiler techniques — see the reference papers.

2

Diverse model support

One accelerator for diverse AI models

The same accelerator supports CNNs — classification, detection, segmentation — as well as generative models, vision Transformers, and language models.

Full-stack flow

A single quantized ONNX model is compiled step by step — Fused IR, L1 and L2 instructions, then hardware microcode — and executed and cross-validated at every level, from the cycle-accurate simulator down to RTL simulation and the FPGA. Hover, tap or focus any box to highlight its inputs and outputs and read what it does.

Compiler

  • In: Quantized ONNX (→ TOSA), via the MLIR compiler (MIDAP HLC)
  • Passes: op-fuse → tile → memory-compile → L1-to-L2 lowering
  • Out: L1 inst. (tile-level, bank-aware), L2 inst. (config/run/wait)

Simulator

  • Accuracy: a cycle-accurate NPU simulator — end-to-end latency including DRAM overhead
  • Levels: high-level (performance & bottlenecks) + low-level (runs microcode)
  • Tracing: Perfetto-compatible export for DMA and core-stall analysis

RTL

  • CNN accelerator RTL: an FPGA-oriented SoC with an IBEX RISC-V control core
  • Bus interfaces: AXI (DRAM model) + APB
  • Verify: RTL simulation

Validated on a Xilinx KCU1500; the RTL is not tied to any specific board or simulator.

FAQ

Is MIDAP open source?

MIDAP is an open NPU (neural processing unit) platform developed by the CAP Lab at Seoul National University. A public open-source release of the full stack — MLIR compiler, cycle-accurate simulator, and RTL — is planned for H1 2027. Join the waitlist to be notified.

Does MIDAP include an NPU simulator?

Yes. The platform includes a cycle-accurate NPU simulator that models the datapath, DRAM traffic, and stalls to report end-to-end latency and bottlenecks, plus a low-level simulator that executes the hardware microcode, with Perfetto-compatible trace export.

Is the RTL validated?

Yes. The CNN accelerator RTL is an FPGA-oriented SoC with an IBEX RISC-V control core and AXI/APB interfaces, validated on a Xilinx KCU1500. The RTL is not tied to any specific board or simulator.
